Honest Limitations

  • This is a rebuilt, simplified analytics engine, not the original Python pipeline. It runs entirely client-side from a single generic "cost" column per transaction rather than the original's separate COGS / shipping / payment-fee breakdown, so numbers are directionally consistent with (not always numerically identical to) the Stage 1-7 notebook pipeline in this repository, which remains the source of truth for exact figures.
  • Returns, if mapped, are treated as fully reversing both revenue and cost on that line. The original pipeline additionally keeps a non-refundable shipping/payment-fee cost even on a return; this simplified engine does not model that distinction.
  • "After marketing cost" allocation treats every transaction row as its own purchase event (spend ÷ rows-per-channel, charged flat to each row), since this tool has no order-ID concept the way the original per-order-line allocation does. For orders with more than one line item, this over-charges each line slightly -- directionally correct, not cent-for-cent identical to the Stage 1-7 pipeline.
  • Cohort retention, dead-stock, and channel-CAC thresholds use fixed default assumptions (6-month cohort window, 3-months-available / 15%-sell-through dead-stock bar, 3.5 assumed customer-lifetime orders) baked into this page's code, not exposed as UI controls.
