# ledger-margin-analysis

Machinery for two independent freight-analysis pipelines, neither
assuming the other has data:

- **Cost/margin**: load and validate a raw invoice-ledger export, clean
  it with every decision logged, allocate costs to compute true
  per-transaction margin under multiple pluggable strategies, slice
  margin by customer/route/month, and check whether an apparent
  pattern survives an obvious alternative explanation.
- **Routing**: load a vehicle trip log (no cost data), detect
  dead-head (empty-running) legs against a distance matrix, quantify
  vehicle utilisation, and price empty km at an explicit, caller-
  supplied diesel rate.

This is an analysis toolkit, not an application, and it ships with no
real data. `data/synthetic/` holds generated datasets for both
pipelines (pure noise, no planted pattern) used to exercise every code
path before real data arrives. Real freight ledgers so far have had
either costed invoice lines or vehicle trip logs, not both - the two
pipelines are built to run independently for exactly that reason.

## Repository layout

```
src/
  schema.py       canonical column definitions for all four input files + validate()
  synth.py        synthetic data generator - ledger+overhead, or trips (--mode trips)
  clean.py        cleaning pipelines: clean() for the ledger, clean_trips() for trips
  margin.py       pluggable cost-allocation strategies -> per-txn margin
  slice.py        grouping utilities (by customer/route/month, concentration)
  confounder.py   stratified/period/mix-shift/timing checks against a finding
  routing.py      dead-head detection, utilisation, empty-km costing
  detect.py       inspects a file's columns, decides which pipeline(s) can run
  pipeline.py     CLI entry point for both pipelines, or --auto + src/detect.py
dashboard/
  app.py          Streamlit dashboard - both pipelines, graceful if one's data is missing
  standalone.html self-contained HTML/JS routing tool - no server, opens in any browser
notebooks/
  01_explore.ipynb  margin + routing usage examples, executed with real output
tests/            pytest suite against synthetic data, for both pipelines
data/
  raw/            gitignored - real exports land here
  processed/       gitignored - output of `make clean-data` / `src/pipeline.py`
  synthetic/       committed - generated by `make synth` / `src/synth.py --mode trips`
  reference/       committed - distances.csv placeholder matrix (see its own README)
```

## Input schema

Four files, all defined in `src/schema.py`:

- **Ledger** (`LEDGER_SCHEMA`) - one row per invoice line: `txn_id`,
  `txn_date`, `txn_type`, `customer_id`, `customer_segment`,
  `origin_id`, `destination_id`, `vendor_id`, `line_item`, `quantity`,
  `uom`, `revenue`, `direct_cost`, `cost_category`, `invoice_id`,
  `payment_date`.
- **Overhead** (`OVERHEAD_SCHEMA`) - one row per month per cost
  category (driver salaries, EMIs, rent, office, etc.): `period_month`,
  `cost_category`, `amount`, `description`. This is the pool of cost
  that isn't attributable to any single transaction; `margin.py`'s
  allocation strategies distribute it across transactions.
- **Trips** (`TRIPS_SCHEMA`) - one row per vehicle trip, no cost
  columns: `txn_id`, `date`, `vehicle_id`, `origin_id`,
  `destination_id`, `revenue`.
- **Distances** (`DISTANCE_SCHEMA`) - a distance matrix: `origin_id`,
  `destination_id`, `km`. `routing.py` looks up km for both loaded and
  empty legs from this file.

`schema.COLUMN_ALIASES` maps common real-world header variants (e.g.
`veh`/`truck` -> `vehicle_id`, `from`/`to` -> `origin_id`/
`destination_id`) to these canonical names; `src/detect.py` uses it so
a differently-headed real export is still recognised.

Every column name is referenced through these constants everywhere
else in the codebase - a schema change (which will happen once real
data arrives) is a one-file edit.

```
pip install -r requirements.txt
```

## Usage

```
make synth        # generate data/synthetic/{ledger,overhead}.csv
make synth-trips   # generate data/synthetic/trips.csv
make clean-data    # run src/clean.py + schema validation -> data/processed/
make clean-trips   # run the routing pipeline -> data/processed/
make test          # run the pytest suite
make dashboard      # streamlit run dashboard/app.py
```

Or open `dashboard/standalone.html` directly in a browser - no `make`
target needed, it's a plain file.

Each target also has a CLI if you want to run it directly, e.g.:

```
python -m src.synth --rows 20000 --seed 42 --out data/synthetic/ledger.csv
python -m src.pipeline --in data/raw/ledger.csv --overhead-in data/raw/overhead.csv --out-dir data/processed
```

For the routing pipeline:

```
python -m src.synth --mode trips --rows 400 --seed 42 --out data/synthetic/trips.csv
python -m src.pipeline --trips data/raw/trips.csv --distances data/reference/distances.csv --out-dir data/processed
```

Or let `src/detect.py` decide which pipeline(s) a file of unknown
shape supports:

```
python -m src.pipeline --auto path/to/some_export.csv --force ledger|trips  # --force is optional
```

`src/pipeline.py` fails loudly (raises) if a cleaned file doesn't pass
`schema.validate()` - it does not write output that looks fine but
isn't.

## Cleaning

`src/clean.py` runs five named steps - `normalise_dates`,
`normalise_ids`, `deduplicate_txn_id`, `flag_customer_name_variants`,
`handle_nulls` - each appending to a decision log (step, rows
affected, rule applied). `clean(df)` returns `(cleaned_df,
decision_log)`; `make clean-data` also writes the log to
`data/processed/decision_log.csv`. Near-duplicate customer IDs are
flagged for review, never auto-merged. Nulls are never imputed -
`handle_nulls` records an explicit, stated policy per nullable column
instead.

## Margin allocation

`src/margin.py` exposes three interchangeable strategies
(`margin.STRATEGIES`), all sharing the signature
`(ledger_df, overhead_df) -> df`:

- `direct_cost_only` - uses `direct_cost` as-is, ignores the overhead
  pool.
- `proportional_by_revenue` - adds each transaction's revenue-share of
  its period's overhead pool on top of known direct cost.
- `per_unit_by_quantity` - same, but shares overhead by quantity
  instead of revenue.

`margin.compute_margin(ledger_df, overhead_df, strategy)` runs one by
name or by passing the function directly. All three add
`allocated_cost`, `margin`, and `margin_pct` columns.

## Slicing and confounders

`src/slice.py` provides `by_customer`, `by_route`, `by_month`,
`by_two_way`, and `concentration` (share of a value held by the top N
groups). `src/confounder.py` provides `stratified_comparison`,
`period_over_period_excluding`, `mix_shift_decomposition`, and
`accrual_vs_cash_view` - each returns a comparison table so you can
check whether an apparent pattern is actually explained by mix, by one
entity, by a volume/rate shift, or by payment timing.

## Routing (empty-running / utilisation)

`src/routing.py`:

- `detect_empty_legs(trips_df, distances_df)` - per vehicle, sorted by
  date, flags a dead-head leg wherever one trip's destination doesn't
  match the next trip's origin. km is looked up from `distances_df`; a
  missing pair gets `km_missing=True` and a null `empty_km`, never a
  silent zero.
- `summarize_vehicle_km` - per-vehicle loaded/empty km and empty %,
  with `missing_km_legs` surfacing any leg (loaded or empty) whose
  distance pair wasn't in the matrix.
- `utilisation` / `utilisation_summary` - idle days between
  consecutive trips per vehicle.
- `price_empty_km(empty_df, diesel_price_per_litre, km_per_litre)` -
  converts empty km to rupees using two required arguments, never a
  hardcoded constant.

## Dashboard and standalone tool

`dashboard/app.py` renders up to five views across both pipelines -
margin by customer/route/month, revenue concentration, and empty km by
vehicle - each independently: missing one pipeline's data (cost or
trips) skips only that pipeline's views with a plain message, not a
crash. It accepts an uploaded trips CSV (`st.file_uploader`) in
addition to reading `data/processed/`. No analysis logic of its own -
every number comes from `src/margin.py`, `src/slice.py`, or
`src/routing.py`.

`dashboard/standalone.html` is a self-contained HTML/CSS/JS routing
tool - open it directly in any browser (phone, tablet, no install, no
server). It ports `src/detect.py`, `clean_trips`, and `src/routing.py`
to plain JavaScript so it can load a trips CSV and a distance matrix
(upload or paste) entirely client-side. It only implements the routing
pipeline - a cost-shaped file gets an honest "not implemented here"
message rather than a fabricated margin computation. Verified to match
the Python pipeline exactly against both the hand-built test fixture
and the full synthetic dataset (see `tests/test_routing.py`).

## Testing

```
make test
```

Tests cover `schema.validate`, each cleaning step, each margin
strategy (with hand-verified expected values), `src/routing.py`
against hand-built fixtures with known answers, `src/detect.py`'s
capability detection, and integration smoke tests for both pipelines,
all run against generated synthetic data.
